Phase Plan · 1 of 3  ·  Flier Canvassing Platform  ·  v1.0

Platform Spine
& the Mycofest Campaign

Ship a working multi-tenant canvassing platform end to end: a host posts targets, a player claims one, posts the flier, and submits a geotagged photo that survives the fraud pipeline and turns a pin from red to green.

Spec: PRD v0.4.0 · READY Constitution v1.0 Budget cap: $4k–$7k build Infra: <$50/mo
01

Objective

Prove the platform can collect verifiably real, target-anchored flier placements inside a budgeted, isolated campaign — the full red→green loop, fraud screening included — with the Mycofest campaign live as the first tenant.

Phase independence: if Phases 2–3 never happen, Phase 1 still delivers a usable Mycofest campaign. Manual settlement means no payment rail is on the critical path — the ledger tracks what's owed and you pay out off-platform.

Resolved stack choices

The constitution left four implementation choices open (§2). Resolved here so tasks can be sized against concrete picks. Any of these is reversible before the data layer is built — flag now if you'd swap one.

Open itemPickWhy
ORM / queryDrizzle ORMFirst-class raw-SQL escape hatch for PostGIS ST_DWithin; Prisma's geospatial support is weak.
Object storageCloudflare R2Zero egress fees — you re-read audit photos repeatedly; S3-compatible API.

08

Top risks

RiskP / ImpactMitigation
Dedupe false-matches legit distinct placements of the identical flier, or misses a reused photo. M / H Different-target gate (T3.3) sidesteps the core false-match. Review gate + threshold tuning on a seeded adversarial set before dependents build. Background-region hashing held in reserve for Phase 3.
Isolation leak — a host sees another campaign's data, or spend crosses budgets. L / H DAL makes unscoped queries structurally impossible (T2.1); automated isolation suite is a hard exit gate (EC-5). Server-side role enforcement, never UI-only.
Claim race — two players claim/fill one target near-simultaneously. M / M Atomic claim + one-claim-per-target at the DB level (T3.2); offline-sync conflict path surfaces "already filled" cleanly (T5.3).
GPS unreliable in dense/forested Mycofest terrain → false rejects at the 40m gate. M / M Proximity radius is per-campaign configurable (loosen for Mycofest); failed proximity routes to human review, not auto-reject.

Kill / restructure criteria

  • Dedupe can't get below a workable false-positive rate even with the different-target gate → escalate to background-region hashing now (pull a Phase-3 item forward) rather than ship a leaky pipeline.
  • Isolation suite can't reach 100% pass on the chosen DAL pattern → stop and redesign the data layer before any surface work.
  • Build crosses the $8k cap before exit criteria met → board review.

Phases 2–3 (sketch)

Planned in detail only when Phase 1 exits. Budget ladders up; each phase is independently valuable.

Phase 2 · Score & Polish

~$3k–$5k build

Leaderboard polish, coverage analytics for hosts, grand-prize ceremony flow, offline-sync hardening, submit-time optimization, accessibility + reduced-motion pass. Inherits all Phase-1 instrumentation.

~$6k–$10k build

Host self-serve campaign creation, host-funded Stripe Connect budgets + automated payouts (introduces payment rail + PCI scope), host dashboards, cross-campaign player profiles, websocket map push, background-region dedupe hardening.
